## 완료

* **질문**: blind3에서 v3-mix는 분리가 되는데(SI-SDRi +3.0 dB, DER −41 %p) WER은 원음보다 57 % 나빴다. 분리기 탓인가, 지표 탓인가?
* **가설(지표)**: 장면 참조 문장은 "화자 A + 화자 B"인데, 분리 스트림의 단어는 시간순으로 합쳐 비교한다. 두 화자가 20~60 % 겹치면 완벽한 분리도 단어 순서가 엇갈려 오류가 된다.
* **구현**
  * `datatools/metrics.py::cp_wer`: 화자별 연결 최소 순열 WER(CHiME-6·MeetEval의 cpWER).
  * `evaluation/asr.py::segments_cp_wer`, `evaluation/compare.py`: 한 번의 인식으로 지금 WER, 게이트 WER, cpWER, 게이트 cpWER을 모두 계산.
  * `training/systems.py::OracleReferences`: 완벽 분리(참조 신호). 진단 전용.
  * `datatools/ami.py::scene_speaker_transcripts`: 장면 주석 구간에서 화자별 문장 복원(이어 붙이면 장면 문장과 같은지 검사).
  * 단계 `asr_diag_dev`(dev만, blind 자료는 열지 않음).
* **결과**(AMI dev 160장면)

  | 시스템 | 지금 WER | cpWER |
  | --- | --- | --- |
  | 원음 | 0.446 | 0.838 |
  | v2 base | 0.866 | 0.929 |
  | v3-mix | 0.699 | 0.718 |
  | v3-real | 0.605 | 0.653 |
  | **oracle(완벽 분리)** | **0.484** | **0.360** |

* **판단(사전 규칙 적용)**: 완벽 분리도 지금 지표로는 원음보다 8.5 % 나쁘다. 지금 지표로는 어떤 분리기도 REQ-402를 통과할 수 없다. 지표가 REQ-402 판정에 맞지 않는다고 결론짓는다.
  * cpWER에서는 oracle이 원음 대비 −57 %로 제대로 구분된다.
  * 분리기 문제도 남는다. v3-mix cpWER 0.718은 oracle 0.360과 거리가 멀다. dev에서 원음 대비 상대 v3-mix −14.3 %, v3-real −22.1 %다(dev는 낙관적).
* **하지 않은 것**: blind2·blind3를 새 지표로 다시 판정하거나 계산하지 않았다. 승인된 §6.2 규칙은 그대로다. 후보도 바꾸지 않았다.
